# Trust boundaries and data policy

Owner: Ievgen Sein. Reviewed for 0.9 Preview, 2026-11-10.

| Boundary / asset | Threat and control | Limit |
|---|---|---|
| Windows process and local files | Run as a standard user. Install in an executable location approved by the site; keep user data outside that folder. ProgramData update policy must be writable only by administrators/system. User settings/captures inherit the user's Windows ACLs. | Another process running as the same user or an administrator can alter ordinary user files. App ownership leases prevent accidental concurrent writers; they are not a security boundary. |
| PLC connection | Explicitly configured read-only S7 memory and diagnostic services use one shared transport per source. No PLC write or RUN/STOP commands are exposed. Network segmentation, approved routes and PLC permissions remain the site's responsibility. | Classic S7 transport does not supply application-level encryption/authentication. Successful reads and configured family do not prove CPU identity or RUN mode. No scanning or inbound app service is enabled. |
| Imported files | Metadata, sample blocks and workspace archives have count/size/schema limits. Workspace import uses fixed generated entry paths, rejects extra/duplicate entries and checks content hashes before activation. Imported acquisition stays stopped. Existing captures are never overwritten. | Hashes detect corruption and bind references; an unsigned workspace/capture is not proof of its author. Treat externally supplied recordings as sensitive, untrusted input. |
| Updates | Outbound HTTPS is restricted to the updater's approved GitHub hosts. Pinned ECDSA signatures, hashes, channel/version policy, withdrawal/freshness controls and recoverable rollback remain enforced for online and offline updates. Managed/offline mode can prevent online checks. | A site's proxy/TLS policy must permit legitimate traffic; a proxy failure is not evidence that the installed app is current. Optional self-signed Preview Windows trust is not a publicly trusted publisher certificate. |
| Reports/support/sharing | Reports offer preview/redaction. Review the exact output before sharing. Workspace export defaults to configuration only; selecting references or copies is explicit. Sanitized review packages contain only driver/type/sampling/count information, no signal/source names, endpoint/address/unit/scaling fields or captures. | Full captures and operational workspaces contain machine metadata and production values. Sanitized review copies deliberately cannot be imported or connected. Never infer that renaming a file anonymizes its contents. |
| Data at rest / retention | Captures remain on user-selected storage, default Documents/SignalLab/DataRecords/yyMMdd. Backups are explicit copies; live cache expires separately. User deletion and storage quotas follow documented app controls. Use site-managed Windows disk protection/ACLs where needed. | There is no cosmetic app password or bespoke encryption. Backup/support/export copies have their own retention responsibilities. No automatic cloud telemetry or capture upload is added by this work. |
| Release supply chain | Locked dependencies, static/dependency/secret checks, native product/update qualification and owner-signed release evidence. Each final archive embeds a CycloneDX inventory of packages, framework versions and file hashes, including native SQLite and the recovery helper. | Inventory is a release snapshot, not a guarantee of absence of vulnerabilities. The SBOM excludes itself from file hashes to avoid circularity; the signed update manifest binds the entire archive. |

## Security intake and handling

The public binary repository's private vulnerability reporting is the intake described in SECURITY.md. The owner reproduces with synthetic data, evaluates affected versions/trust boundaries, retains private investigation evidence, prepares a correction and release notes, then coordinates disclosure. Avoid publishing original capture values or identifying plant details in a security advisory. No secrets, private keys or credentials belong in support bundles or the repository.

## Identified validation limits

Native fixtures run with a non-administrator token and isolated settings. A real loopback CONNECT/TLS fixture exercises the HTTP stack without modifying Windows proxy or certificate stores. This does not certify a customer proxy, domain policy, physical 16 GB PC, mixed-DPI workstation or PLC firmware. Those checks remain explicit site acceptance work.

Inventory format: [CycloneDX 1.6 JSON specification](https://cyclonedx.org/docs/1.6/json/). Field definitions and runtime/native file hashes come from the built artifact, not a hand-maintained component list.
